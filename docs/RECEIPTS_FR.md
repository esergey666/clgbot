# Чек Франция: итальянские наименования, PNG

## Итоговые требования

Последние уточнения пользователя заменяют исходные требования к PDF и фиксированной высоте:
- выдаётся только PNG;
- ширина 80 мм, 300 DPI, 945 пикселей;
- две обычные позиции: 2244 пикселя / примерно 190 мм;
- одна позиция короче; каждая следующая позиция и дополнительные строки увеличивают высоту;
- шрифт остаётся одинакового размера, текст не сжимается ради фиксированной длины;
- наименования пользователь вводит на итальянском, поле модели называется `name_it`;
- максимум 20 позиций. Количество единиц в позиции может быть больше одной.

Печатать PNG следует в масштабе 100%, отключив подгонку под страницу.
Физический размер растрового файла округляется до целого пикселя: при 300 DPI один пиксель равен примерно 0,085 мм.

## Запуск в Telegram

Главное меню → «Создать • примеры» → «Франция · чек + ценники».
Прямой запуск: `/receipt_fr`.

Порядок ввода: дата → количество → итальянское название → размер → цвет → артикул для ценника → полная цена (Retail Price) → цена аутлета (Outlet Price). Штрихкод генерируется автоматически; вводить его не нужно.
«Сегодня» или `-` подставляет текущую дату по часовому поясу магазина (Europe/Paris).
После каждого товара доступны «Добавить товар», «Закончить», «Отмена».
Перед выдачей показываются все позиции, дата, сгенерированное время, итог, HT, TVA, наличная оплата и сдача.
«Изменить данные» запускает ввод заново. «Создать чек и ценники» отправляет PNG чека и отдельный PNG ценника для каждой позиции.

Стоимость берётся из существующей настройки «Чек» в админ-панели, по умолчанию 300 за весь комплект (чек и ценники), а не за позицию.
Генерация требует доступа. При ошибке рендера баланс не списывается; повтор отправки после сетевой ошибки в текущем диалоге не списывает баланс ещё раз.
FSM хранится в памяти, как в существующем боте: перезапуск процесса сбрасывает незавершённые диалоги.

## Пример ввода (каждое поле отдельным сообщением)

Дата: `23.09.2026`

| Поле | Товар 1 | Товар 2 |
|---|---|---|
| Количество | 1 | 1 |
| Наименование | GIUBBOTTO SENZA MANICHE | FELPA CON CAPPUCCIO |
| Размер | XXL | L |
| Цвет | NERO | GRIGIO |
| Артикул | 8115G0123 | 811564151 |
| Цена единицы | 395 | 170,50 |

Итог: 565,50 EUR; HT: 471,25 EUR; TVA: 94,25 EUR; оплачено: 600,00 EUR; сдача: 34,50 EUR.
Если у второго товара количество 2, итог будет 736,00 EUR, всего 3 единицы.

Полная сериализованная структура `Receipt` находится в `docs/receipt_example.json`.
Денежные значения сериализуются строками и восстанавливаются как Decimal; внутри моделей `purchase_date` и `purchase_time` имеют типы date/time.
`ReceiptItem.line_total` и `Receipt.article_count` — вычисляемые свойства.

## Настройки

Реквизиты по умолчанию перенесены из предоставленного образца. Они меняются переменными `STORE_NAME`, `STORE_ADDRESS_1`, `STORE_ADDRESS_2`, `STORE_PHONE`, `STORE_EMAIL`, `STORE_LEGAL_NAME`, `STORE_VAT_NUMBER`.
Часы: `STORE_OPEN=10:00`, `STORE_CLOSE=20:00`; часовой пояс `STORE_TIMEZONE=Europe/Paris`.
Ставка Decimal("0.20"), валюта EUR и список консультантов задаются в `bot/receipts/config.py`.
Служебные идентификаторы синтетические; receipt/document/sale ID генерируются из UUID, остальные — случайно. Это не интеграция с кассой магазина.
Code 39 содержит отдельный синтетический `barcode_value` вида `01B` + 10 цифр (формат прочитан со скана). Он связан с `receipt_id` через полный объект чека в PNG. Видимого QR нет, как и в исходном скане. JSON для QR и полный объект чека сохраняются в текстовых метаданных PNG (`receipt_qr_payload`, `receipt`).
Наименования не переводятся автоматически и проверяются на непустой ввод/длину, а не на принадлежность языку.

## Оформление по образцу

Узкий моноширинный шрифт Inconsolata, четыре колонки реквизитов, компактные строки товаров и номера EAN-13 под ними. Артикул печатается только на ценнике. Таблица TVA имеет отдельные колонки Taxe/Montant/Taux/Base HT. Внизу восстановлены консультант, дата, текст возврата из образца, A01 и синтетические контрольные строки. Большой QR и подписи технических полей из первой версии не печатаются.

`assets/receipt_fr/` содержит два начертания шрифта и лицензию OFL.

### Уточнение шрифтов и кодов

Receipt Mono — производное Inconsolata с обычным нулём без диагонали; исходные контуры остальных символов сохранены, ширина и кегли подогнаны к скану. Лицензия и описание изменений находятся в `assets/receipt_fr/`.

Штрихкод Code 39 печатается с начальным и конечным `*`, без дополнительного контрольного символа. Звёздочки являются служебными знаками, декодер возвращает только `barcode_value`.

`control_code` — 96 символов Base64 от 72 случайных байтов, печатаемых двумя строками по 48. Это синтетический служебный код, не настоящая фискальная подпись. UUID остаётся в метаданных и не печатается вместо нижней строки.

`cashier_name` генерируется один раз при предпросмотре; список имён задаётся `STORE_CASHIERS=Alexandre,Thomas,Louis,Sophie`. Имя показывается в сводке и в блоке консультанта/кассира на чеке. При повторной отправке имя, штрихкод и нижний код не меняются.

Для отсутствующего цвета можно ввести `-`: этот знак не печатается в строке товара.


## Комплект: чек и ценники 50 × 25 мм

На каждую позицию автоматически создаётся синтетический внутренний EAN-13 с проверенной контрольной цифрой. Это не зарегистрированный производителем GTIN. `product_barcode` создаётся один раз при добавлении товара и сохраняется в модели, предпросмотре и PNG-метаданных. На ценнике закодирован тот же номер, который напечатан под товаром в чеке. Code 39 самого чека остаётся отдельным идентификатором документа.

Дополнительные поля ReceiptItem:
- `retail_price: Decimal` — полная цена;
- `unit_price: Decimal` — цена аутлета за одну вещь; только она участвует в сумме чека;
- `product_barcode: str` — автоматически созданный EAN-13.

Артикул `article` нужен для верхней строки ценника и не подставляется вместо штрихкода в чек.

Пример: артикул `801563750`, цвет `V0041`, наименование `FELPA`, размер `XXL`, Retail Price `255,00`, Outlet Price `170,50`. При количестве 2 сумма строки чека — `341,00`, на ценнике остаются цены одной единицы: `255,00` и `170,50`.

Цена аутлета не должна превышать полную цену. Для старых сериализованных объектов без Retail Price полная цена принимается равной цене продажи; новый диалог всегда запрашивает обе цены.

Ценник повторяет белую наклейку на предоставленном скане, без окружающей чёрной картонной бирки. PNG имеет 1000 × 500 пикселей и 508 DPI, что даёт ровно 50 × 25 мм. Печать — 100%, без подгонки. Штрихкод отрисован целыми пиксельными модулями, без масштабирования полос.

Одна позиция: 3 файла. Пять позиций: 11 файлов (чек, 5 ценников и 5 базовых наклеек). Даже если количество единиц в позиции больше одной, отправляется один ценник на позицию — его можно распечатать нужное число раз. При сетевой ошибке отправка продолжается с недоставленного файла в текущем диалоге; повторного списания нет.

Новые файлы:
- `bot/receipts/product_codes.py` — генерация EAN-13 и проверка контрольной цифры;
- `bot/receipts/price_tag.py` — рендер белого ценника и набора ценников;
- `tests/test_french_price_tags.py` — соответствие чек/ценник, размеры, цены, валидация EAN-13.

Обновлены models.py, renderer.py, handlers.py, обе клавиатуры, версия и тесты диалога. Тесты покрывают отправку всех ценников и восстановление после сбоя между файлами.


## Базовая наклейка 50 × 25 мм

`base_sticker.py` создаёт дополнительный PNG на каждую позицию: EAN-13 справа, Data Matrix слева, артикул/цвет/размер и итальянское наименование. Размер 1000 × 500 пикселей при 508 DPI. Штрихкод позиции общий для чека, ценника и базовой наклейки.

На предоставленном скане прочитан EAN `8052572986499`, Data Matrix `8052572986499000010000036`: первые 13 цифр совпадают с EAN, далее 12 цифр `000010000036`. Видимый верхний номер `598087478656` и нижнее `076` не входят в эти данные. По одному образцу нельзя определить назначение этих полей или алгоритм производителя.

Генератор создаёт собственные синтетические `sticker_serial` (12 цифр), `sticker_suffix` (12 цифр), `sticker_code` (3 цифры). Это не подтверждение подлинности и не восстановленный алгоритм производителя. Значения сохраняются вместе с позицией и не меняются при повторной отправке. Data Matrix содержит EAN позиции и её суффикс.

Сначала рендерится весь комплект, затем выполняется одно списание. Прогресс доставки каждого типа файлов сохраняется отдельно. При повторе после сетевого сбоя уже отправленные файлы не отправляются заново.

### Шрифты наклеек

Сжатый Arial заменён на Roboto Condensed с отдельными начертаниями (веса 500 и 650). Подпись EAN использует собственные пиксельные цифры 5 × 7 с перечёркнутым нулём, отрисованные целыми квадратами без сглаживания. Верхний номер базовой наклейки — Inconsolata Bold; нижний 25-значный номер — сильно сжатый Roboto Condensed. Для каждого текстового блока отдельно настроены высота и ширина по скану. Шрифты включены в репозиторий: результат не зависит от шрифтов Windows или Linux. Это визуальное приближение; название оригинального шрифта по скану не установлено.


### Калибровка по сканам (версия 2026.09.23-8)

Координаты заданы на холсте 1000 × 500. Ценник: начало полос EAN (103, 200), обычные полосы высотой 190, защитные 225, подпись на y=403. Базовая наклейка: полосы (475, 58), высоты 172/195, подпись y=238; чёрная область Data Matrix (45, 94), размер 280 × 280. Верхний номер (45, 39), нижний (37, 395), описание справа начинается в (494, 305).

Пиксельные цифры сравнивались с сеткой исходного скана. В нём есть образцы 0, 2, 4, 5, 6, 7, 8, 9; отсутствующие 1 и 3 дополнены в том же стиле. Для исходной строки Data Matrix подтверждено совпадение всех 324 модулей 18 × 18 при ASCII-кодировании. Для новых значений рисунок кодов закономерно меняется.

Точное название исходных текстовых шрифтов не установлено. Это калиброванный макет, а не заявление о стопроцентном пиксельном совпадении с отсканированной печатью. Коды производителя не генерируются: служебные поля новых товаров остаются синтетическими.
