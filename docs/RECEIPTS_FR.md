# Чек Франция: итальянские наименования, PNG

## Итоговые требования

Последние уточнения пользователя заменяют исходные требования к PDF и фиксированной высоте:
- выдаётся только PNG;
- ширина 80 мм, 300 DPI, 945 пикселей;
- две обычные позиции: 2244 пикселя / примерно 190 мм;
- одна позиция короче; каждая следующая позиция и дополнительные строки увеличивают высоту;
- шрифт остаётся одинакового размера, текст не сжимается ради фиксированной длины;
- наименования пользователь вводит на итальянском, поле модели называется `name_it`;
- максимум 20 позиций. Количество единиц в позиции может быть больше одной.

Печатать PNG следует в масштабе 100%, отключив подгонку под страницу.
Физический размер растрового файла округляется до целого пикселя: при 300 DPI один пиксель равен примерно 0,085 мм.

## Запуск в Telegram

Главное меню → «Создать • примеры» → «Чек Франция · PNG».
Прямой запуск: `/receipt_fr`.

Порядок ввода: дата → количество → итальянское название → размер → цвет → артикул → цена одной единицы.
«Сегодня» или `-` подставляет текущую дату по часовому поясу магазина (Europe/Paris).
После каждого товара доступны «Добавить товар», «Закончить», «Отмена».
Перед выдачей показываются все позиции, дата, сгенерированное время, итог, HT, TVA, наличная оплата и сдача.
«Изменить данные» запускает ввод заново. «Создать чек» отправляет PNG документом.

Стоимость берётся из существующей настройки «Чек» в админ-панели, по умолчанию 300 за весь чек, а не за позицию.
Генерация требует доступа. При ошибке рендера баланс не списывается; повтор отправки после сетевой ошибки в текущем диалоге не списывает баланс ещё раз.
FSM хранится в памяти, как в существующем боте: перезапуск процесса сбрасывает незавершённые диалоги.

## Пример ввода (каждое поле отдельным сообщением)

Дата: `23.09.2026`

| Поле | Товар 1 | Товар 2 |
|---|---|---|
| Количество | 1 | 1 |
| Наименование | GIUBBOTTO SENZA MANICHE | FELPA CON CAPPUCCIO |
| Размер | XXL | L |
| Цвет | NERO | GRIGIO |
| Артикул | 8115G0123 | 811564151 |
| Цена единицы | 395 | 170,50 |

Итог: 565,50 EUR; HT: 471,25 EUR; TVA: 94,25 EUR; оплачено: 600,00 EUR; сдача: 34,50 EUR.
Если у второго товара количество 2, итог будет 736,00 EUR, всего 3 единицы.

Полная сериализованная структура `Receipt` находится в `docs/receipt_example.json`.
Денежные значения сериализуются строками и восстанавливаются как Decimal; внутри моделей `purchase_date` и `purchase_time` имеют типы date/time.
`ReceiptItem.line_total` и `Receipt.article_count` — вычисляемые свойства.

## Настройки

Реквизиты по умолчанию перенесены из предоставленного образца. Они меняются переменными `STORE_NAME`, `STORE_ADDRESS_1`, `STORE_ADDRESS_2`, `STORE_PHONE`, `STORE_EMAIL`, `STORE_LEGAL_NAME`, `STORE_VAT_NUMBER`.
Часы: `STORE_OPEN=10:00`, `STORE_CLOSE=20:00`; часовой пояс `STORE_TIMEZONE=Europe/Paris`.
Ставка Decimal("0.20"), валюта EUR и список консультантов задаются в `bot/receipts/config.py`.
Служебные идентификаторы синтетические; receipt/document/sale ID генерируются из UUID, остальные — случайно. Это не интеграция с кассой магазина.
Code 39 содержит отдельный синтетический `barcode_value` вида `01B` + 10 цифр (формат прочитан со скана). Он связан с `receipt_id` через полный объект чека в PNG. Видимого QR нет, как и в исходном скане. JSON для QR и полный объект чека сохраняются в текстовых метаданных PNG (`receipt_qr_payload`, `receipt`).
Наименования не переводятся автоматически и проверяются на непустой ввод/длину, а не на принадлежность языку.

## Оформление по образцу

Узкий моноширинный шрифт Inconsolata, четыре колонки реквизитов, компактные строки товаров и артикулы под ними. Таблица TVA имеет отдельные колонки Taxe/Montant/Taux/Base HT. Внизу восстановлены консультант, дата, текст возврата из образца, A01 и синтетические контрольные строки. Большой QR и подписи технических полей из первой версии не печатаются.

`assets/receipt_fr/` содержит два начертания шрифта и лицензию OFL.

### Уточнение шрифтов и кодов

Receipt Mono — производное Inconsolata с обычным нулём без диагонали; исходные контуры остальных символов сохранены, ширина и кегли подогнаны к скану. Лицензия и описание изменений находятся в `assets/receipt_fr/`.

Штрихкод Code 39 печатается с начальным и конечным `*`, без дополнительного контрольного символа. Звёздочки являются служебными знаками, декодер возвращает только `barcode_value`.

`control_code` — 96 символов Base64 от 72 случайных байтов, печатаемых двумя строками по 48. Это синтетический служебный код, не настоящая фискальная подпись. UUID остаётся в метаданных и не печатается вместо нижней строки.

`cashier_name` генерируется один раз при предпросмотре; список имён задаётся `STORE_CASHIERS=Alexandre,Thomas,Louis,Sophie`. Имя показывается в сводке и в блоке консультанта/кассира на чеке. При повторной отправке имя, штрихкод и нижний код не меняются.

Для отсутствующего цвета можно ввести `-`: этот знак не печатается в строке товара.
